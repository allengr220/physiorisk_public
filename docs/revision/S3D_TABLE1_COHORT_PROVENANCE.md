# Sprint 3D: Table 1 and cohort-flow provenance

## Scope and decision rule

This ledger audits the submitted manuscript and the newest canonical provenance chain in this repository. It does not reopen TotalRisk, validation, or model development. The targeted regeneration pass used `scripts/run_s3d_cohort_regeneration.py`, which imports the exact cycle loader from notebook 01, and `scripts/run_s3d_table2_export.py`, which executes the scientific comparison cells from notebook 05. No model was fit or modified by the cohort regeneration script.

Classification at the end uses:

- **A — reproducible now:** retained executable producer plus available public or verified input route; no unidentified scientific step.
- **B — externally/manual sourced but adequately documentable:** manuscript/manual assembly is legitimate provenance, although an external source may still need citation verification.
- **C — requires regeneration from an identified producer:** producer and inputs are known, but the required output is absent or the current committed output begins downstream.
- **D — genuinely unresolved:** no exact producer/source or defensible reconstruction route is known.

The manuscript text immediately preceding the table says the values were “taken from NHANES public documentation” and represent interviewed/public-use participants, with separate selected/interviewed/examined reporting for later cycles. The table caption states that these are source-cycle counts before mortality linkage, adult eligibility, biomarker availability, and benchmark restrictions.

No local spreadsheet, standalone table export, manuscript comment, footnote/endnote, or cycle-specific source note was found. The DOCX has no comments part. Its general references point readers to the NHANES and linked-mortality websites, but the exact cycle documentation supporting the three examined counts is not retained locally. Therefore external-source verification of 9,338, 9,813, and 9,544, and confirmation of the precise CDC pages used during manual assembly, is **pending**. This is not evidence that the table is scientifically unreproducible.

The nine original/interviewed values were computationally reproduced from downloaded files. `notebooks/01_nhanes_extended_dataset_builder.ipynb` contains cycle labels, folders, suffixes, and candidate filenames, but **contains no hard-coded participant counts**. For each cycle, `load_cycle()` reads the downloaded DEMO XPT and calculates the count as `len(out)`; the concatenated source population is calculated as `len(source)`. The regeneration script contains expected counts only as post-download assertions, not as data inputs. All nine downloaded DEMO files, URLs, byte sizes, SHA256 hashes, and parsed row counts are recorded in `tables/s3d_nhanes_input_manifest.csv`; their observed rows sum to 92,062. The same run downloaded and hashed the nine 2019 linked-mortality files and independently found the same per-cycle row counts. The three examined values are not generated by notebook 01 because its row base is DEMO/interviewed participants.
